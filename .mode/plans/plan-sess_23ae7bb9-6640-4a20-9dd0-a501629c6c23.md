## P2 全量改名：Mode / ZCODIUM → Mode

依据：仓库自带的 `docs/specs/p0-user-facing-naming.md`（P0，已完成）与 `p1a-external-env-renames.md`（P1a，已完成）已把「改名」分成三阶段，P2 原文写着"转独立维护时处理"——本次就是执行 P2，并把 P1a 的 `MODE_` 再推进到 `MODE_`。规模盘点：`@mode/*` 29 个包 / 2049 个文件含 import，全仓含 `mode` 的文件约 2900 个。

### S0 准备（1 个提交）

- 新增 `docs/specs/p2-mode-naming.md`：改名清单、三段兼容规则、必须保留项、验收标准（按 AGENTS.md 要求"先 spec 后实现"）。
- 写 `scripts/` 下的一次性改名脚本（幂等、可复跑），所有机械替换走脚本 + `git diff --stat` 逐段核对，避免手工漏改。

### S1 环境变量：三段链 + 内部变量

- `packages/shared/src/env-names.ts` 扩成 `MODE_` 优先 → `MODE_` → `MODE_` 三段（读取端逐级回退、写入端全名双写/三写，弃用告警按前缀去重）；补上目前没有回退的 `MODE_DATA_ROOT_ACTION`，并把一直裸露的 `MODE_HOME` 纳入名单。
- 新增一批 `MODE_*` 覆盖用户/CI/安装器真的会设置的变量（`.env.example`、`mise.toml`、`installer.mjs`、dev 脚本、`release.yml`）。
- 其余约 336 个进程间内部 `MODE_*`（390 文件）机械替换为 `MODE_*`——按 P1a 的结论，内部变量不需要兼容层。
- 验证：`packages/shared/test/env-names.test.ts` 扩写三段断言；`pnpm typecheck` + lint。

### S2 包名与目录（最大的一刀，单独一个提交）

- `@mode/*` → `@mode/*`：29 个包的 `name`、115 处 `workspace:*` 依赖、3261 条 import（2049 文件）、`pnpm-lock.yaml` 重新生成。
- 保留两个易漏项的处理：根包 `mode` → `mode`、`apps/mode-cli` 的 `mode-cli` → `mode-cli`；`packages/mode-server-cli`（包名 `@mode/server-cli`）与 `packages/mode-cua`（包名 `@mode/cua`）目录与包名不一致，一并规整。
- 目录改名：`apps/mode-cli` → `apps/mode-cli`、`packages/mode-cua` → `packages/mode-cua`、`packages/mode-server-cli` → `packages/mode-server-cli`、`scripts/mode-distribution` → `scripts/mode-distribution`、`packages/shared/src/mode-protocol{,-v4}` → `mode-protocol{,-v4}`、`packages/services/src/mode-{agent,session}` → `mode-{agent,session}`。
- 同步配置：`pnpm-workspace.yaml`、`architecture-policy.yaml`（roots/publicEntrypoints）、`knip.json`、`turbo.json`、`scripts/*.mjs`（含 `build-desktop-agent-cli.mjs` 的 12 包构建顺序表）、22 个测试文件里的 `@mode/` mock 键、`.github/workflows/*` 的 `pnpm --filter`。
- 内部标识符：`modeAgentService` / `modeSessionService` / `mode-protocol` 类型与目录、`window.mode`（127 处，renderer↔main 同版本发布，无外部依赖）。
- 验证：typecheck + lint + services/desktop/ui 测试 + `architecture:check` + `knip`；本地起一次 dev 实例确认可启动。

### S3 产物名与命令名

- `dist/mode.cjs` → `dist/mode.cjs`（CLI build/SEA 脚本、桌面 `bundled-agents/.../glm/mode.cjs`、`electron-builder.config.js` 的引用同步）；`bin.mode` → `bin.mode`、`CLI_COMMAND_NAME = "mode"`、`installer.mjs` 的安装目录与提示、TUI 的 `PRODUCT_NAME`（连带 `scripts/mode-distribution-smoke.mjs` 的断言）。

- 验证：本地 build CLI + 一次 Windows 安装包，确认字节码/SEA 资产键（`mode-provider/*`）改名后仍能加载。

### S4 数据根与迁移（决定"用户数据不能消失"的一步）

- `packages/shared/src/data-root.ts`：新根名 `.mode`；legacy 名单变成多代 `.mode`（并保留更早的 `.mode`）；`DATA_ROOT_PRODUCT_ID` 改为 `dev.mode.app` 并加**可接受旧 id 名单**，避免存量根被判 `unowned` 而备份让路。
- 冲突/备份目录前缀改 `.mode.*`，同时识别旧 `.mode.*` 前缀以便清理。
- Electron `userData` 目录名 `Mode` → `Mode`：首次启动在新路径不存在时把旧目录迁移过去（失败则继续用旧目录并记录日志，绝不丢状态）。
- 全仓 91 文件 / 180 处 `.mode` 路径字面量机械替换（凭证、设备、CLI 配置、session store、skills/settings-sync、debug server、exportLogs 等）。
- 验证：扩充并跑通 `dataRootInitializer/dataRootOwnership/dataRootMigration/dataBaseDirEnvLock` 四个测试；实机用一份现有 dev 数据目录验证自动迁移（迁移后设置、机器人、凭证仍在）。

### S5 插件与生态改名（带迁移，你选的是彻底）

- 市场 id `zcode-plugins-official` → `mode-plugins-official`：适配器为官方市场做 id 覆盖（清单里声明的是官方名），并在启动时**迁移已落盘数据**——用户设置 `enabledPlugins`、`installed_plugins.json`、插件 cache 目录、内置插件 id 常量、图标资源目录与 `modeOfficialPluginIcons.generated.ts`。
- 清单目录 `.zcode-plugin/plugin.json` → `.mode-plugin/plugin.json`：新名为主，**同时继续读旧路径**（第三方插件不作废），本仓库随包的两个内置插件改用新目录。
- `.zcodeignore` → `.modeignore`（读新名、兼容旧名），项目级 `.mode/` 配置目录同样新名为主、旧名兼容。
- 验证：实机确认已装插件（browser-use / node-repl-host）与商店「公开/个人」两段仍正常，第三方目录（Claude）不受影响。

### S6 协议与对外标识（改名 + 接受旧值）

- `MODE_PROTOCOL_NAME` → `"Mode Protocol"`：服务端**同时接受**旧名，保证 SSH 远端旧 agent 混布仍能握手。
- LAN cookie `mode_lite_token` → `mode_lite_token`（读旧 cookie 兜底，脚本 `verify-lan-attach.mjs` 同步）。
- MCP `_meta` 前缀 `com.mode/*` → `com.mode/*`（读旧 key 兜底 + 迁移已存认证）。
- deep link `mode://` → `mode://`：注册新 scheme 并处理旧 scheme 链接（不主动注册旧 scheme，避免与宿主 Mode 争抢——这同时也修掉现在两个应用抢 `mode://` 的问题）。
- 企业微信二维码来源标识 `WECOM_QR_SOURCE`、HTTP 客户端 `appName: "Mode"` → Mode；前者实机创建一次二维码验证平台接受，不接受则回退。
- 保留：`MODE_VERSION` 编译期 define 之外不再有 magic string；`LICENSE-APACHE` 的 Z.AI 署名、两份 NOTICE 的上游段落、THIRD-PARTY-NOTICES 全部第三方原文、ai-elements 头注释、`upstream-audit.yml` 里的真实远端仓库名 `ZCodium-project/ZCodium` 一律不动（写进 spec 的"必须保留"清单）。

### 风险与取舍（明确写出）

- `@mode/*` → `@mode/*` 之后与上游 Mode 的路径、包名、协议名彻底分叉，以后同步上游改动需要手工对应——这是"全量"的必然代价。
- S2 是唯一有全局性风险的一步（2049 文件），用一次性脚本 + 全量闸门 + 本地实机兜底，并且单独一个提交便于回退。
- 迁移相关（数据根、插件 id、userData）都采用"新名为主 + 旧值兼容"的写法，任何一条迁移失败都不会删除旧数据，只会保留旧路径继续运行。
- 本地无法验证的部分（第三方台账重生成、macOS/Linux 产物）在 CI 里补验，我会在报告里如实标注。

# 局域网连接（LAN remote connection）

同一网段内的两台机器上各跑一个 Mode，一台作为**服务方**（把工作区开放给对端），另一台在
「远程连接 → 局域网」里搜索、配对、选择工作区后开始对话。默认全部关闭。

## 服务方（被连接的那台）

1. 设置 → **局域网访问** → 打开「允许局域网访问」。
   - 首次开启时系统（Windows 防火墙）会询问网络权限，请允许**专用网络**访问。
   - 卡片会显示 `正在监听 192.168.x.y:45880`（端口默认 45880，被占用时自动改用其它端口）。
2. 点「生成配对码」，把 6 位配对码发给要连接的设备（5 分钟内有效、一次性）。
3. 「已配对设备」列出所有已换到长期令牌的客户端，可逐个移除；「重置全部令牌」会让所有
   已配对设备重新配对。

服务方只通过 HTTP/WS 暴露 **工作区列表 + 受信 RPC 通道**，且：

- 未持令牌访问 `/api/server-info`、`/ws*`、`/api/*` 一律 401；
- 发现应答（UDP 45879）里**不含任何令牌**，只含设备名、端口、版本；
- 通过 HTTP/WS 暴露的「写入凭据」（Provider Provisioning target）永远是会失败的占位实现，
  局域网对端无法把凭据写进本机。

## 连接方

1. 打开任意工作区 → 输入框左侧「项目」下拉 → **远程连接**（或空会话页的同一入口）。
2. 第 1 步选「局域网」→「下一步」。
3. 第 2 步：等 1~2 秒的广播发现结果出现（同一台机器上的实例也会被发现），点选设备；
   路由器开了 AP 隔离、或防火墙拦了 UDP 时列表为空，直接在「地址/端口」手动填入服务方
   卡片上显示的地址。
4. 首次连接输入对端显示的配对码 → 点「配对」（显示「已配对：设备名」）→「开始连接」。
   令牌存进本机凭据服务，以后在同一设备上重连不再需要配对码。
5. 连接就绪后选择要打开的对端目录即可开始对话。

## 校验脚本

```bash
# 在仓库根目录（脚本需要 packages/desktop 的依赖）
node --import tsx packages/desktop/scripts/verify-lan-attach.mjs <host> <port> <pairCode> [dir]
```

它会依次验证：未授权 401 → 配对换令牌 → 服务端工作区列表 → host capability →
`/ws/host` 受信通道升级 → 通过通道跑一次真实 RPC（`IFileService.readdir`）。
配对码一次性，重跑前请在设置卡点「重新生成」。

## 已知限制（v1）

- 只做 **UDP 广播发现**（零依赖）；跨网段、VPN/Tailscale 等场景请用手动填地址。
- 服务方目前只有 **Mode 桌面端**（设置里的开关）；`zcode serve`/Web 版协议兼容但还没有开关。
- 局域网连接暂不支持随消息**上传附件**（会给出明确报错），也不提供依赖本地 stdio backend 的
  能力（打开本地编辑器等）；文件、Git、终端、会话都走同一条受信通道，正常可用。
- 目前「选择远程目录」在局域网连接下仍停在加载中：通道本身可用（见上面的校验脚本），
  渲染端远程工作区层对 `lan` 的分支还没接完。

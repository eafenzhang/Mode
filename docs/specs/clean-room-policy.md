# Spec：clean-room 自研纪律

前置：路线图 `docs/plans/2026-10-09-tauri-rewrite-roadmap.md`（M0–M5）Global Constraints 第一条。
本 spec 把那条约束落成可评审的过程纪律；`AGENTS.md`「核心原则」末尾有指针行指向本文件。

## 目的

为路线图的「产品自研」目标定义过程纪律：新增与重写代码只从允许输入出发编写，
不参考上游 `zai-org/ZCode` 或本仓库上游衍生的实现，使 M4 终态能以
「与 `upstream/zcode-baseline` 分支逐文件 diff = 0」验收。

## 适用范围

| 面                                                     | 适用性     | 说明                                                           |
| ------------------------------------------------------ | ---------- | -------------------------------------------------------------- |
| `crates/**`                                            | 适用       | 全部新写                                                       |
| `apps/desktop-tauri/**`                                | 适用       | 全部新写                                                       |
| M4 替换的新前端                                        | 适用       | 替换 `packages/ui` 的 clean-room 实现                          |
| M2+ 的任何新模块                                       | 适用       | 新增与重写代码一律适用                                         |
| 第三方 vendored：`.agents/skills/**`、`third-party/**` | **不适用** | 由 `third-party/copied-components.json` 台账治理，按台账纪律走 |
| 旧代码的日常 bugfix                                    | **不适用** | 只修行为不重写；若借机重写，重写部分回到适用范围               |

本仓库约 56% 行数为上游衍生（路线图口径）。哪些文件属上游衍生不靠个人判断：
M4 的 `scripts/upstream-overlap-check.mjs`（对基线分支逐文件哈希 + 改名归一哈希）就绪前，
以上游基线分支 `upstream/zcode-baseline`（已存在，= 29628c9）的逐文件 diff 结果为准；
脚本就绪后以脚本产物为准。

## 核心规则

### 允许输入

编写新代码只允许取材于：

- 本仓库的 spec（`docs/specs/**`）、协议定义、测试；
- `DESIGN.md`；
- 公开 API 文档与公开资料。

### 禁止输入

- 不读取、不打开、不搜索、不引用上游 `zai-org/ZCode` 的实现源码；
- 不读取本仓库中上游衍生的实现文件作为编写参考（约 56% 那部分；识别口径同上：对
  `upstream/zcode-baseline` 逐文件 diff，M4 脚本就绪后以脚本产物为准）；
- 翻译、对照改写、"按上游思路复现"均属读实现，一律禁止。

### 黑盒对拍

- 允许：运行旧实现（本地或基线分支检出），观察输入输出与事件序列，作为行为规格；
- 不允许：打开旧实现的源码照着写「重写版」。对拍只比行为，不看实现。

### AI 辅助规则

- 提示词与上下文不得包含上游或衍生实现文件的内容（含粘贴、摘录、让模型先读再改）；
- 生成结果若与上游实现出现**非接口约定所致**的逐字雷同，丢弃重写，并自查雷同来源。

### 违规处置

- 评审中发现即打回，并在 PR 说明中记录违规事实；
- 同一模块重复违规，该模块整体重做。

## 与门禁的关系

- M4 的 `pnpm verify:self-developed`（含 `upstream-overlap-check` 对 `upstream/zcode-baseline`
  逐文件 diff = 0%）是**终态硬门禁**，事后判定；
- 本 spec 是**过程纪律**，保证在到达终态前不再新增重合。门禁与纪律缺一不可：
  门禁兜底，纪律省掉返工。

## 评审检查项（PR checklist）

- [ ] 本 PR 新增代码的输入来源都在允许清单内；
- [ ] diff 中没有上游文件路径或上游实现内容的引用（含注释、示例、提示词模板）；
- [ ] AI 生成部分做过雷同自查：非接口约定所致的逐字雷同已丢弃重写；
- [ ] 行为对拍只记录观察到的输入输出与事件序列，没有粘贴旧实现代码；
- [ ] 若援引「vendored / 旧代码 bugfix」豁免，豁免依据已写明且未夹带重写。

## 验收

1. 适用范围、允许输入、黑盒对拍、AI 规则、违规处置、终态门禁引用六项齐全且互不矛盾。
2. `grep -c "clean-room-policy" AGENTS.md` 输出 1；指针行位于「核心原则」列表末尾。
3. 终态：M4 运行 `verify:self-developed`，与 `upstream/zcode-baseline` 逐文件 diff = 0%。

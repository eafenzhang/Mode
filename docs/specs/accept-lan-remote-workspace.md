# 真机验收：LAN 远程工作区（`remote` 频道翻面）

> 状态：待执行（2026-11-23 翻面后）。全自动测试覆盖到「换票 → WS 握手 → Initialize →
> RPC 往返」（`crates/host-channels/tests/remote_lan_port.rs`，4 条），但**真实双机
> 配对、令牌、端点探测与断线重连**必须双机验证。

## 0. 前置

- 两台机器都装同一版本（含本次翻面）。
- 两台机在同一局域网（或一端能通过公网中继访问另一端）。
- 被配对侧（下称 **B**）已开启「局域网访问」。

## 1. 配对（B 侧出码，A 侧输码）

| # | 操作 | 期望 |
| --- | --- | --- |
| 1.1 | B：设置 → 局域网访问 → 开启 | 显示端口与地址列表 |
| 1.2 | B：生成配对码 | 出现 8 位码，有倒计时 |
| 1.3 | A：输入配对码 | 配对成功，B 的客户端列表出现 A 的条目 |
| 1.4 | A：检查凭据 | `lan:peer:<serverId>:token` 与 `:meta` 均已写入 |
| 1.5 | B：撤销/重置令牌 | A 的连接立刻失败，报「令牌无效或已被重置，需要重新配对」 |

## 2. 连接与 attach

| # | 操作 | 期望 |
| --- | --- | --- |
| 2.1 | A：连到 B 的某个工作区 | `connect` 返回 `{ok:true,descriptor}`；`descriptor.target` **不含令牌** |
| 2.2 | A：打开该工作区 | 文件树/会话列表能加载（说明 `attach` 的 scoped 服务面已在工作） |
| 2.3 | A：再连同一工作区 | 复用同一条连接（`listSessions` 两条、底层 WS 一条） |
| 2.4 | A：连 B 的第二个工作区 | 复用同一条连接（同一 `host:port`） |

## 3. 断线与重连

| # | 操作 | 期望 |
| --- | --- | --- |
| 3.1 | 拔掉 A 的网线 3 秒 | 会话变 `disconnected`/`sourceAvailability=offline`；不卡在 connecting |
| 3.2 | 恢复网络 | 重连成功或明确报错（**不得**永久挂起） |
| 3.3 | B：关闭局域网访问 | A 的会话断开；A 侧不残留半开连接 |
| 3.4 | B：重启应用 | A 重连后能继续用（新 `Initialize` 后订阅被重放） |

## 4. 未落地传输的降级（应显示可读错误，不是崩溃）

| # | 操作 | 期望 |
| --- | --- | --- |
| 4.1 | A：连一个 SSH 目标 | 报「SSH 远程工作区尚未支持：需要 SSH 客户端（未落地）」 |
| 4.2 | A：连一个 WSL 目标 | 报「WSL 远程工作区尚未支持…」 |
| 4.3 | A：连一个 v3 目标 | 报「v3 远程工作区尚未支持：需要 Noise 端到端传输（未落地）」 |
| 4.4 | 上述任一失败后 | A 的会话列表**不残留**该条目；重试依然能失败（不卡 busy） |

## 5. 回滚

| # | 操作 | 期望 |
| --- | --- | --- |
| 5.1 | A：`MODE_HOST_INPROCESS_CHANNELS=none` 重启 | `remote` 由 Node Host 提供，LAN 远程工作区照常可用 |
| 5.2 | 5.1 之后检查日志 | 无「inprocess channel not constructible」之类的告警噪声 |

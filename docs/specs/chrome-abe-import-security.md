# Spec：Chrome App-Bound 导入的安全要求（spike 门禁）

状态：**草案**，随 `docs/plans/2026-10-17-chrome-abe-import-spike.md`（B 路线）一起评审。
适用范围：任何读取/解密当前用户 Chrome app-bound cookie 或密钥的能力（helper、扩展、
Native Messaging、CDP、电梯调用、进程内调用/注入）。现有 C# helper 与 Rust P1 在结论出来前
保持现状，不在本 spec 的放行范围内。

## 1. 目的

把「能解密」与「可以发布」分开：本 spec 只定义**发布前必须满足的安全条件**，
不规定具体技术路径。技术路径仍然优先选择受支持、无注入的方案（见 spike 的 P1–P4）。

## 2. 威胁模型（必须逐条回答）

1. **本机其他进程**：能否在我们不察觉时触发解密、读取结果或复用通道？
2. **恶意/被篡改的 helper 或扩展**：如何证明运行的二进制/扩展就是签名的那个？
3. **数据外传**：cookie 或密钥是否可能离开本机、进入日志/崩溃报告/遥测？
4. **权限提升**：是否要求管理员/服务；提权后能做什么；如何限制爆炸半径？
5. **持久化**：密钥、cookie 值、授权状态是否被落盘；多久、谁能读？
6. **拒绝服务/竞态**：重复导入、并发导入、Chrome 更新/退出时会发生什么？
7. **企业/受管设备**：是否会绕过管理员策略；能否被策略禁用？
8. **误用与滥用**：用户被诱导点击后，攻击者能获得什么；如何让用户看到真实范围？

## 3. 要求

| # | 要求 | 验收证据 |
| --- | --- | --- |
| R1 | **逐次授权**：每次导入都由用户的明确动作触发；不持久化“已允许提权/解密” | UI/协议记录；重放测试 |
| R2 | **仅当前用户 profile**：不接受任意路径/任意用户；路径由受信任的发现逻辑给出 | 入参校验用例；越权路径负控 |
| R3 | **数据最小化**：只取导入所需的 cookie/localStorage；不读取密码、支付、历史等无关数据 | 数据流图；抓包/日志审查 |
| R4 | **不落盘敏感物**：密钥与 cookie 值不写日志、崩溃报告、遥测、磁盘；只在内存中用到即弃 | 日志审查；字符串扫描；失败路径审查 |
| R5 | **完整性**：helper/扩展/app 的身份可验证（签名/哈希/来源）；失败 fail-closed | 签名/哈希校验用例；负控（篡改/换钥） |
| R6 | **最小权限**：能不用管理员就不用；不新增常驻服务，除非评审明确接受并写明理由 | 权限清单；安装/卸载验证 |
| R7 | **受支持机制优先**：扩展/Native Messaging/CDP/电梯优先；注入是最后手段，必须单独评审 | 路径选择记录；否证证据 |
| R8 | **可审计**：只记录数量、reason、耗时；不记录值；用户可查看最近一次导入结果 | 日志样本；UI 结果 |
| R9 | **可关闭/可回滚**：有本地开关或构建开关；失败不破坏现有 C#/P1 路径 | 开关用例；回滚演练 |
| R10 | **合规**：用户自有数据；不绕过企业策略；评估 Chrome 商店/ToS 与当地法律 | 政策评估记录；法务/安全签字 |

## 4. 数据流（必须画出来并评审）

```text
用户点击导入
  → 受信任的发现逻辑（profile 路径）
  → chosen mechanism（扩展/电梯/注入…）
  → 仅内存中的 cookie 值/密钥
  → 写入内置浏览器的目标 session
  → 丢弃敏感物，仅返回计数与 reason
```

评审时必须标出：每一步的进程边界、权限、失败语义、日志点、可被谁触发。

## 5. 评审门禁（spike 的 go 条件）

- [ ] 威胁模型 8 条都有明确答案与残余风险；
- [ ] R1–R10 逐条有证据（负控优先）；
- [ ] 至少一次多引擎 AV/EDR 扫描（若涉及注入/进程内调用）；
- [ ] 企业策略禁用路径可用；
- [ ] 失败路径不泄露密钥/cookie，不留下半截状态；
- [ ] 法务/安全评审签字；
- [ ] 若 go：另出实现 spec（含版本检测、失败码、回滚）与实现计划；若 no-go：登记并保留 C#/P1。

## 6. 非目标

- 不规定具体 COM 接口、注入框架或扩展实现细节；
- 不改变现有 helper 契约（`docs/specs/browser-import-helper-contract.md`）；
- 不为“能解密”而降低上述任何一条要求。
